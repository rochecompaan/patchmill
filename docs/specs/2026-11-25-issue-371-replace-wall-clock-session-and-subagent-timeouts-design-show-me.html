What stops each session

Session pi.timeoutMinutes: null (default) Cap set
Unattended implementation No deadline. Stall policy ends a hang. Cap, Cap checkpoint 5 min before, Stall policy.
Unattended planning No deadline. Stall policy (new) ends a hang. Cap, Cap checkpoint, Stall policy.
Interactive planning and implementation No deadline. The maintainer is present. Cap. A first Console worker spawn gets the pi-subagents checkpoint; a resume gets none.
Triage (print mode) Built-in 90-minute backstop. Cap, no checkpoint.
Subagent child 2,147,483,647 ms (largest value pi-subagents accepts). Checkpoint 5 min before. The managed agents reviewer and patchmill-implementation carry the same deadline in frontmatter, so resumes and chain steps get it too. Cap from the child's start. Checkpoint 5 min before.

Why the parent's cap is always first

  • A child gets the same length of deadline, but it starts later, so it never ends before its parent by default.
  • The Cap checkpoint asks the parent to wait for its children and hand off before the cap.
  • With no cap, neither has a deadline in practice. The Stall policy watches the parent and its child sessions together.

Config values

  • null: no cap (default).
  • A number greater than 0 and at most 35791: the cap in minutes.
  • Anything else: ConfigError.
